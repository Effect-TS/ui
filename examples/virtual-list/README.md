# VirtualList example

One page per `VirtualList` feature. Start it with `pnpm dev` in this folder and open the printed URL. The index links to each page, and `?demo=<name>` opens one directly.

## Pages

| `?demo=`   | What it shows                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :--------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `header`   | Content above the list changes size without a scroll. The header grows from 100px to 600px, and the rows on screen follow it whether the page scrolls or a `viewport` around the header and the list does.                                                                                                                                                                                                                                                                                                               |
| `shell`    | A scroller the list doesn't render. A layout's `<main>` scrolls, and the page inside it has no `viewport` part, so the list names it with `scrollContainer`. "Jump to 5,000" sends the same target with a new `id`, so it scrolls again each time.                                                                                                                                                                                                                                                                       |
| `paged`    | Page 5 of a 10,000-result search, 50 results per page. `firstPosition: 201` makes each result say where it sits in the whole set. "Unknown total" passes `setSize: -1`, which ARIA reads as a total that isn't known. The third option leaves both props out.                                                                                                                                                                                                                                                            |
| `fixed`    | `measure: false` with CSS that disagrees. `.row` has `min-height: 32px`, and `.padded` adds 12px of padding above and below a 16px line plus a 1px border, so each row would be 41px. The list writes 32px on each row, so the layout it computes is the one on screen.                                                                                                                                                                                                                                                  |
| `chat`     | A chat that loads older messages as the user scrolls up. 50 of 500 messages are loaded, and a page of 50 takes 500ms. `reserveStart` keeps room above the oldest loaded message until the first one has arrived. The messages pass only `keys`, which sets the count and keeps the rows on screen in place when a page lands before them.                                                                                                                                                                                |
| `progress` | A reading-progress bar from the scroll offset, and a count of finished scrolls. Every `Scrolled` carries the offset and `scrolling`. With `trackScroll`, the list sends one for each change of the offset. Without it, the list sends one only when the visible rows, an edge or `scrolling` changes, so the bar moves in steps and catches up when a scroll ends. A scroll has finished when `scrolling` turns false. The list part also carries `scrolling`, for rows that skip costly content while the list scrolls. |
| `table`    | A native table of 10,000 rows with a sticky header. The browser sizes the columns, and the list stands in for the rows it leaves out with empty rows in the `<tbody>`. The header row is row 1, so the list passes `firstPosition: 2`.                                                                                                                                                                                                                                                                                   |
| `absolute` | Rows placed with a transform (`layout: "absolute"`). The same rows render in either layout, and a row that grows moves the rows after it. Only the absolute layout animates the rows, since a transition in the flow layout would animate the switch between the two. `sizes` gives every row its real height up front, so the rows above never shift as estimates change, which the transition would show as a jump.                                                                                                    |
| `grid`     | A responsive grid scrolled by the page. The lanes and the gap come from the CSS, so resizing the window changes the columns.                                                                                                                                                                                                                                                                                                                                                                                             |
| `big`      | 100,000 measured rows of three heights, for a performance trace.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## History check

`check-history.mjs` loads every older page of the `chat` page in a real browser and checks that the message under the pointer stays where it was when each page lands. Run it from the repository root, or as `pnpm check-history` in this folder:

```sh
node examples/virtual-list/check-history.mjs [chromium|firefox|webkit] [--executable <path>]
```

It needs the browsers of the `playwright` dev dependency (`pnpm exec playwright install`). `--executable` picks another browser build.

The check starts the example's Vite server itself and scrolls with Playwright's synthesized wheel. The chat starts at message 450 of 500, so there are nine landings: 450 to 400, and so on down to 50 to 0, where `reserveStart` is dropped. Each landing must be measured. A landing that never arrives, or one that arrives while the wheel is still moving the list, fails the run.

On every frame, after it is painted, the page records the loaded start, the scroll position and the top of each message in one task. For each landing, the check takes the message under the pointer in the last frame before the new page, or the first message below the pointer when it sits between two. It compares that message with itself in the first frame after the page lands and three frames later, without rounding. Neither may move more than 1px.

After the run, the check replays its own samples three ways that must fail: with one landing missing, with one landing still scrolling, and with one message moved by 1.01px. The process exits with 1 when the run fails or when a replay passes.
